Instance admins open **Instance settings** from the account menu. This is where the settings of the whole installation live, next to the instance's accounts, workspaces and health.

<InstanceSettingNote setting="Environment settings moving into the dashboard">
These settings are being moved from environment variables into Instance settings: who can create workspaces, sign-in methods, limits, SMTP, the Slack app and the instance's single sign-on providers. For each of them: set it in Instance settings, or by the environment variable as the initial value. This page is updated as each one lands; until then, check the page in your version of the dashboard.
</InstanceSettingNote>

## What the page shows today

The current Instance settings page lists these settings with the environment variable behind each (the page names the variable next to the setting):

| Section | Setting | Environment variable |
|---|---|---|
| Dashboard address | The address, and old addresses that redirect to it | `PUBLIC_URL`, `PREVIOUS_PUBLIC_URLS` |
| Sign-in methods | Which methods the instance accepts (password, email code, single sign-on) | `AUTH_PASSWORD_ENABLED`, `AUTH_EMAIL_ENABLED`, `AUTH_SSO_ENABLED` |
| Who can create workspaces | Instance admins only, or everyone | `WORKSPACE_CREATION` |
| Storage and limits | The storage driver, default retention of new projects, the grace period before unused files are deleted, the upload timeout, whether webhooks may call private addresses | `STORAGE_DRIVER`, `DEFAULT_PROJECT_RETENTION_DAYS`, `GC_GRACE_HOURS`, `UPLOAD_TIMEOUT_MINUTES`, `WEBHOOK_ALLOW_PRIVATE_ADDRESSES` |
| Hosted sites | The sites domain, or "Not set up" | `STATIC_SITES_HOST` |
| Mail | The SMTP server and sender, and a button that sends a test mail to your own address | `SMTP_*` |

<Aside type="caution">
Today these entries show what the server was started with. The goal is that they become editable in the dashboard, with the environment variable acting as the **initial value**. Until a setting is editable, change it by the environment variable and restart. `DEFAULT_PROJECT_RETENTION_DAYS` appears on the page as an environment name but isn't read by the configuration schema in the repository: check `packages/config/src/schema.ts` before relying on it.
</Aside>

## The other instance pages

- **Workspaces**: every workspace on the instance, and creating one. Instance admins manage accounts and workspaces but see the projects only of the workspaces they belong to.
- **Accounts**: every account; change an email, ban or unban.
- **Health**: checks (the same findings as `circi admin doctor`), services including queue depth, the domains and cookies check, and the **Setup code**.
- **GitHub App**: create the GitHub App with the manifest flow, or see the one configured. See [GitHub](/integrations/github/).

See [Instance administration](/using/instance-administration/) for how admins use these pages.

## Settings that stay environment variables

Deployment-level values stay environment variables: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `PUBLIC_URL`, `HOST`, `PORT`, the storage settings, `TRUSTED_PROXIES`, `CIRCI_DIFF_ENGINE`. The full list, with the ones moving marked, is the [environment variable reference](/reference/environment-variables/).
