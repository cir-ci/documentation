Instance admins open **Instance** in the sidebar, then **Instance settings**. The page holds the settings of the whole installation, and most of them can be changed there, with no restart.

## Which value applies

Every setting has up to three sources, and the first one that exists wins.

1. **The environment variable**, when it is set. The setting is locked: the page shows **Set by VARIABLE**, its control is disabled, and a save through the API is refused with "Set by VARIABLE in the environment: change it there."
2. **The value saved in the dashboard.**
3. **The default.**

<InstanceSettingNote setting="Changes apply without a restart">
A saved setting takes effect within about 30 seconds on every server and worker process, because each one re-reads the stored settings on a timer. The process that served the save uses it at once. Changing an environment variable still needs a restart.
</InstanceSettingNote>

To hand a setting over to the dashboard, remove its variable and restart once. To lock it again, set the variable.

<Aside type="note" title="Secrets are write-only">
A password or client secret is never shown again after it is saved: the page only says that one is saved. Secrets are encrypted before they reach the database (sealed at rest). Leave a secret field empty to keep the saved one, and type a new value to replace it.
</Aside>

## What you can change

Each section of the page saves with **Save changes**, and **Discard** reverts it. The two exceptions are the single sign-on providers and the GitHub App, which apply from their own dialogs.

### Who can create workspaces

<SettingCard name="Let every signed-in account create workspaces" defaultValue="off (instance admins only)" type="WORKSPACE_CREATION">
Off, only instance admins create workspaces, and everyone else joins through an invitation or a verified email domain. On, every signed-in account can.
</SettingCard>

### Sign-in methods

<SettingCard name="Password, Email code, Single sign-on" defaultValue="all on" type="AUTH_PASSWORD_ENABLED, AUTH_EMAIL_ENABLED, AUTH_SSO_ENABLED">
The outer limit. Each workspace can turn methods off for its own people, never on beyond this. Email codes need a mail server, and single sign-on needs at least one provider.
</SettingCard>

Saving refuses a change that would leave nobody able to sign in, for example turning the password off while email codes have no mail server. The message says which method to keep.

### Single sign-on providers

GitHub, Google, GitLab and OpenID Connect providers for every workspace. **Add provider** opens a dialog with the provider, the **Name on the sign-in button**, the **Client ID**, the **Client secret**, an **Issuer** for OpenID Connect or a **GitLab address** for a self-managed GitLab, and whether the provider only reports addresses its people own. The dialog shows the redirect address to register at the provider.

A provider set by the `AUTH_*` variables is listed as **Set by AUTH_GITHUB_*** (or the provider's own name), and can't be edited or removed here.

### Mail server

The SMTP **Host**, **Port**, **Use TLS from the start**, **User name**, **Password** and **From address**, and **Send a test mail to your own address**. **Remove the mail server** turns mail off again. With `SMTP_HOST` set the section is locked and shows the server and sender. Without mail, nobody gets sign-in codes, invitations or new sign-in notices.

### Slack app

The **Client ID** and **Client secret** of the Slack app CirCI posts as, and **Remove the Slack app**. With `SLACK_CLIENT_ID` set, the section is locked. See [Slack](/integrations/slack/).

### Storage and limits

| Setting on the page | Variable | Default | Range |
|---|---|---|---|
| New projects keep builds for | none (a dashboard setting only) | 30 days | 1 to 3650 |
| Unused files are deleted after | `GC_GRACE_HOURS` | 24 hours | 0 to 8760 |
| A build still uploading fails after | `UPLOAD_TIMEOUT_MINUTES` | 60 minutes (0 never) | 0 to 10080 |
| Finished background jobs are kept for | `JOB_RETENTION_DAYS` | 14 days (0 keeps them) | 0 to 3650 |
| A webhook receiver may take up to | `WEBHOOK_TIMEOUT_SECONDS` | 10 seconds | 1 to 600 |
| Largest hosted site | `STATIC_SITES_MAX_MB` | 200 MB | 1 to 5000 |

<ScreenFrame name="host-instance-limits" aspect="16 / 10" alt="The Storage and limits section: Local disk with its variable, then number fields for new project retention, unused files, upload timeout, job retention and webhook timeout, and the Hosted sites section saying Not set up." caption="Storage and limits and Hosted sites. A limit set by its variable shows the variable and a disabled field." width={760} />

**New projects keep builds for** is the retention a new project starts with. It is a real setting with no environment variable: each project then changes its own in its settings, and the instance value doesn't touch existing projects. See [Retention and garbage collection](/self-hosting/retention-and-gc/).

## Read-only on this page

These name their variable and are changed there, with a restart.

| Setting | Variable |
|---|---|
| Dashboard address, and the old addresses that redirect to it | `PUBLIC_URL`, `PREVIOUS_PUBLIC_URLS` |
| Storage driver | `STORAGE_DRIVER` and the `S3_*` settings |
| Whether webhooks may call private addresses | `WEBHOOK_ALLOW_PRIVATE_ADDRESSES` |
| Hosted sites domain, or "Not set up" | `STATIC_SITES_HOST` |

Deployment values that don't appear on the page at all: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `HOST`, `PORT`, `TRUSTED_PROXIES` and `CIRCI_DIFF_ENGINE`. The [environment variable reference](/reference/environment-variables/) marks every variable that is also editable in the dashboard.

## The other Instance pages

| Page | What it does |
|---|---|
| **Accounts** | Every account. Change an email, ban or unban. |
| **Workspaces** | Every workspace on the instance, deleted ones too, and creating one. Instance admins see a workspace's projects only if they belong to it. |
| **Health** | The same checks as `circi admin doctor`, the background jobs per queue, the domains and cookies check, and the **Setup code**. |
| **GitHub App** | Create the GitHub App with the manifest flow, or see the one configured. See [GitHub](/integrations/github/). |
