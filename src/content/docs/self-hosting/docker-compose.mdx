## The base file

`docker compose up -d --build` runs two services:

- **postgres** (`postgres:18-alpine`) with a named volume `pgdata`, a health check, user and database `circi`, and the password from `POSTGRES_PASSWORD`.
- **circi**, built from `deploy/Dockerfile`, command `all` (server and worker in one process), published on `CIRCI_PORT` (default 3000). Files go to the `files` volume at `/var/lib/circi/files`. It waits for Postgres to be healthy, then applies migrations on start.

Everything the app reads comes from the `environment:` list, filled from `.env` (or the shell, or `--env-file`). The list has every [environment variable](/reference/environment-variables/) the server reads, so any of them set in `.env` reaches the container; one left empty counts as unset. The compose file builds `DATABASE_URL` from `POSTGRES_PASSWORD`, and fixes `STORAGE_PATH` to the volume. `.env.example` names every variable, most of them commented out.

For storage in S3 without the overlay, set `STORAGE_DRIVER=s3` and the `S3_*` variables in `.env`.

## Settings file

Copy `.env.example` to `.env`. `POSTGRES_PASSWORD` and `BETTER_AUTH_SECRET` are required. For production also set:

| Variable | Why |
|---|---|
| `PUBLIC_URL` | The https address people use, e.g. `https://ci.acme.io`. Links in emails, pull request comments and OAuth redirects use it. |
| `TRUSTED_PROXIES` | The reverse proxy's address or range, so sign-in rate limits see real client addresses. |
| `SMTP_*` | Email codes and invitations. |

Every variable is in the [environment variable reference](/reference/environment-variables/).

## Overlays

```sh
# S3-compatible storage with a local SeaweedFS (development)
docker compose -f docker-compose.yml -f docker-compose.s3.yml up -d --build

# TLS for the dashboard and the sites domain, with Caddy
docker compose -f docker-compose.yml -f docker-compose.caddy.yml up -d --build
```

For production S3 point `S3_*` at AWS S3, Cloudflare R2, Backblaze B2 or similar instead of running the overlay's SeaweedFS. See [Storage](/self-hosting/storage/) and [TLS and reverse proxy](/self-hosting/tls-and-reverse-proxy/).

The Caddy overlay gives the Compose network a fixed subnet, `CIRCI_SUBNET` (`192.168.250.0/24`), and Caddy a fixed address in it, `CADDY_ADDRESS` (`192.168.250.10`): the only proxy the app trusts. Change both if the subnet overlaps a network the host has to reach, such as your VPC.

To run published images with Terraform instead, see [Terraform](/self-hosting/terraform/).

## Running the server and worker separately

`command: ['all']` is right for a small install. To scale, run two services from the same image with `command: ['serve']` and `command: ['worker']`. See [Scaling the worker](/self-hosting/scaling-the-worker/).

## First run

Open `PUBLIC_URL` and follow the setup page, or script it. The server commands run inside the container.

<Steps>

1. **Print the setup code.** The setup page asks for it.

   ```sh
   docker compose exec circi circi admin setup-code
   ```

2. **Create the first account.** Make it an instance admin.

   ```sh
   docker compose exec circi circi admin user create --email you@acme.io --name "You" --instance-admin
   ```

3. **Create a workspace and a project.** The project command prints its CI token once.

   ```sh
   docker compose exec circi circi admin workspace create --name "Acme" --owner you@acme.io
   docker compose exec circi circi admin project create --org acme --name "Web app"
   ```

4. **Check the install.**

   ```sh
   docker compose exec circi circi admin doctor
   ```

</Steps>

<Aside type="tip">
`circi admin doctor` checks storage, the database and its migrations, mail, free disk space, the dashboard address, and the cookie scope of the domains. It exits 1 if anything warns or fails, so it works in a deploy script.
</Aside>

## What the image runs

One bundle, `/app/dist/main.mjs`, plus `/app/migrations` (`CIRCI_MIGRATIONS`), `/app/web` (`CIRCI_WEB_DIST`) and a small `node_modules` (`sharp`, `pg`, the AWS SDK). The image sets `NODE_OPTIONS=--enable-source-maps`, so stack traces point at source files. The image doesn't contain the upload CLI.

The image sets `NODE_ENV`, `HOST`, `PORT`, `STORAGE_PATH`, `CIRCI_MIGRATIONS` and `CIRCI_WEB_DIST` for its own layout.

Health endpoints: `GET /healthz` (liveness, with the version running) and `GET /readyz` (the database and storage answer).
