CirCI is one image plus Postgres. Upgrading is: back up, build the new image, start it, and let it migrate.

<Steps>

1. **Back up** the database (and the storage if it's local disk). See [Backups](/self-hosting/backups/).
2. **Read the changes** in the repository since your version, especially new migrations in `packages/db/migrations` and new environment variables.
3. **Pull and rebuild.**

   ```sh
   git pull
   cd deploy
   docker compose up -d --build
   ```

4. **Migrations run on start.** `serve`, `worker` and `all` apply pending migrations before they start serving, unless started with `--no-migrate`. Look at the log for the migration messages, and run `docker compose exec circi circi admin doctor`.

</Steps>

## Running migrations yourself

For a deployment where several instances start at once, or where you want a step in your pipeline, apply the migrations first and start the app with `--no-migrate`:

```sh
docker compose run --rm circi migrate          # applies migrations and exits
# command: ['serve', '--no-migrate'] and ['worker', '--no-migrate'] for the long-running services
```

## Rolling deploys

Background jobs are rows in the database and **outlive a deploy**. A new version has to understand jobs queued by the old one, and the old one may still be running while the new starts. The project's rule is that a job name or payload key is never changed without a rolling-deploy plan, so upgrades between adjacent versions are safe to roll. If you skip many versions, stop the old workers and let the queue drain first (Instance settings, Health shows the queue depth), then upgrade.

<Aside type="caution">
Migrations are forward-only SQL. There's no automatic downgrade: to go back to an older version, restore the backup you took in step 1.
</Aside>

## Things that sign people out or break links

- Changing `BETTER_AUTH_SECRET` signs everyone out.
- Moving the dashboard to another host: set `PREVIOUS_PUBLIC_URLS`. See [TLS and reverse proxy](/self-hosting/tls-and-reverse-proxy/).
- Changing the storage driver: copy the files with `circi admin storage migrate` first.

## Versions

The image is built from the repository and has no published tag scheme. Note the commit you deployed (`git rev-parse HEAD`) so you can reproduce it or roll back.
