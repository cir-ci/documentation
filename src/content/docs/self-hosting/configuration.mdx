CirCI is configured through **environment variables**, read once at start by `@circi/config`. A bad configuration stops the process with one line per problem (`Invalid configuration: - BETTER_AUTH_SECRET: is required …`) before anything starts.

The full list, with defaults, is the [environment variable reference](/reference/environment-variables/).

## The minimum

Two variables are required. `PUBLIC_URL` has a default that only suits trying CirCI on one machine. Everything else is optional.

<SettingCard name="DATABASE_URL" type="URL" required>
The Postgres connection string. See [Database](/self-hosting/database/).
</SettingCard>

<SettingCard name="BETTER_AUTH_SECRET" required>
Signs sessions and cookies. Generate it with `openssl rand -base64 32`.
</SettingCard>

<SettingCard name="PUBLIC_URL" type="URL" defaultValue="http://localhost:3000">
The https address people open, such as `https://ci.acme.io`. Set it for any install other people use.
</SettingCard>

## Rules between variables

Some variables only make sense together. The server checks them at start and prints one line per problem.

| Variables | Rule |
|---|---|
| `STORAGE_DRIVER=s3` | Needs `S3_BUCKET`. `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` are both set or both left out. |
| `SMTP_HOST` | Needs `SMTP_FROM`. `SMTP_USER` goes with `SMTP_PASSWORD`. |
| `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_WEBHOOK_SECRET` | All three or none. |
| `AUTH_OIDC_ISSUER`, `AUTH_OIDC_CLIENT_ID`, `AUTH_OIDC_CLIENT_SECRET` | All three or none. |
| `AUTH_GITHUB_*`, `AUTH_GOOGLE_*`, `AUTH_GITLAB_*`, `SLACK_*` | Each `_CLIENT_ID` with its `_CLIENT_SECRET`, or neither. |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Both or neither, and a matching P-256 pair. |
| `PUBLIC_URL`, `PREVIOUS_PUBLIC_URLS` | `PUBLIC_URL` is the root of its own hostname. The previous list can't contain the current host. |
| `STATIC_SITES_HOST` | Refused if it's the dashboard host, its parent or child, or shares its parent domain. |
| `AUTH_EMAIL_ENABLED=true` | Without SMTP this only logs a warning, and email sign-in stays off. |
| `AUTH_PASSWORD_ENABLED=false` | Needs email codes to be available, or nobody could sign in. |

## Where a setting lives

- **Environment variables** are for the deployment: addresses, secrets, storage, timeouts, the diff engine.
- **Instance settings** in the dashboard hold the settings an instance admin should change without a restart: who can create workspaces, sign-in methods, limits, mail, Slack and single sign-on providers. A variable that is set wins and locks its setting; otherwise the saved value applies, then the default. See [Instance settings](/self-hosting/instance-settings/).
- **Workspace settings** and **project settings** hold what workspace owners and admins decide: [Workspace settings](/using/workspace-settings/), [Project settings](/using/project-settings/).

## Secrets

`BETTER_AUTH_SECRET` signs sessions and cookies: keep it stable (changing it signs everyone out) and back it up. Don't commit `.env`.

Any variable can also come from a file: set `<NAME>_FILE` to its path, and the server reads the value from it (one trailing newline is dropped). That's how Docker and Kubernetes secrets are mounted, and how the [Terraform module](/self-hosting/terraform/) passes every secret, so none sits in the container's environment. Setting both `<NAME>` and `<NAME>_FILE` is an error, and so is a file the server can't read.

```sh
SMTP_PASSWORD_FILE=/run/secrets/smtp_password
GITHUB_APP_PRIVATE_KEY_FILE=/run/secrets/github_app_key   # the PEM file as it is
```

The secrets are `BETTER_AUTH_SECRET`, `DATABASE_URL`, `SMTP_PASSWORD`, `S3_SECRET_ACCESS_KEY`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_WEBHOOK_SECRET`, `SLACK_CLIENT_SECRET`, `VAPID_PRIVATE_KEY` and the `AUTH_*_CLIENT_SECRET`s.
