CirCI is configured through **environment variables**, read once at start by `@circi/config`. A bad configuration stops the process with one line per problem (`Invalid configuration: - BETTER_AUTH_SECRET: is required …`) before anything starts.

The full list, with defaults, is the [environment variable reference](/reference/environment-variables/).

## The minimum

```sh
DATABASE_URL=postgres://…
BETTER_AUTH_SECRET=<openssl rand -base64 32>
PUBLIC_URL=https://ci.acme.io
```

Everything else has a default or is optional.

## Rules between variables

Some variables only make sense together; the server checks them at start:

- `STORAGE_DRIVER=s3` requires `S3_BUCKET`, and `S3_ACCESS_KEY_ID` with `S3_SECRET_ACCESS_KEY` (both or neither).
- `SMTP_HOST` requires `SMTP_FROM`; `SMTP_USER` goes with `SMTP_PASSWORD`.
- `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` and `GITHUB_APP_WEBHOOK_SECRET` are set all three or none.
- `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` are set together, and must be a matching P-256 pair.
- `PUBLIC_URL` is the root of its own hostname; `PREVIOUS_PUBLIC_URLS` can't contain the current host.
- `STATIC_SITES_HOST` is refused if it is the dashboard host, its parent or child, or shares its parent domain.
- `AUTH_EMAIL_ENABLED=true` without SMTP only logs a warning: email login is off.
- `AUTH_PASSWORD_ENABLED=false` needs email codes to be available, or nobody could sign in.

## Where a setting lives

- **Environment variables** are for the deployment: addresses, secrets, storage, timeouts, the diff engine.
- **Instance settings** in the dashboard hold the settings an instance admin should change without a restart. This is being rolled out: see [Instance settings](/self-hosting/instance-settings/).
- **Workspace settings** and **project settings** hold what workspace owners and project admins decide: [Workspace settings](/using/workspace-settings/), [Project settings](/using/project-settings/).

## Secrets

`BETTER_AUTH_SECRET` signs sessions and cookies: keep it stable (changing it signs everyone out) and back it up. Don't commit `.env`. Secrets can be passed as ordinary environment variables or with your orchestrator's secret mechanism; the variables take the value itself, not a file path.

<Aside type="note">
The compose file only passes through the variables it lists. See [Docker Compose](/self-hosting/docker-compose/).
</Aside>
