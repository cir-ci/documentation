The `circi` command inside the Docker image is the **server** command. It reads the same environment variables as the server (it needs `DATABASE_URL` and the storage settings for most commands), so run it in the container:

```sh
docker compose exec circi circi admin doctor
```

It's not the upload CLI (see [CLI reference](/ci/cli/)). Commands that act inside a workspace take `--org <slug>`; the flag keeps its name from when workspaces were called organizations. Expected failures print one line and exit 1. `--debug` (or `DEBUG=1`) prints a stack trace.

## Processes

<RefList>
<RefItem>
<Fragment slot="term">`circi all`</Fragment>

HTTP server and worker in one process (small installs).
</RefItem>
<RefItem>
<Fragment slot="term">`circi serve`</Fragment>

The HTTP API and web UI.
</RefItem>
<RefItem>
<Fragment slot="term">`circi worker`</Fragment>

Background jobs (diffing, notifications).
</RefItem>
<RefItem>
<Fragment slot="term">`circi migrate`</Fragment>

Apply database migrations and exit.
</RefItem>
</RefList>

`serve`, `worker` and `all` migrate on start unless `--no-migrate`.

## `circi admin …`

Every command starts with `circi admin`. Add `--help` to any of them.

### Accounts and workspaces

<RefList>
<RefItem>
<Fragment slot="term">`user create --email --name [--password] [--instance-admin] [--json]`</Fragment>

Create an account. There's no self sign-up. The password needs at least 12 characters; without `--password` one is generated and printed once.
</RefItem>
<RefItem>
<Fragment slot="term">`user set-password --email [--password] [--json]`</Fragment>

Set a new password.
</RefItem>
<RefItem>
<Fragment slot="term">`workspace create --name --owner <email> [--slug] [--json]`</Fragment>

Create a workspace owned by an existing account.
</RefItem>
<RefItem>
<Fragment slot="term">`workspace list [--json]`</Fragment>

List workspaces.
</RefItem>
<RefItem>
<Fragment slot="term">`member add --org --email [--role owner|admin|member]`</Fragment>

Add an existing account to a workspace (default role `member`).
</RefItem>
<RefItem>
<Fragment slot="term">`auth enable|disable <email|password> --org`</Fragment>

Change a workspace's allowed sign-in methods. Skips the check that refuses a change leaving nobody able to sign in, so it's the way back in when a setting locked everyone out.
</RefItem>
</RefList>

### Projects

<RefList>
<RefItem>
<Fragment slot="term">`project create --org --name [--slug] [--default-branch main] [--member <email>…] [--json]`</Fragment>

Create a project and print its CI token.
</RefItem>
<RefItem>
<Fragment slot="term">`project list --org [--json]`</Fragment>

List a workspace's projects.
</RefItem>
<RefItem>
<Fragment slot="term">`project rotate-token --org --project [--json]`</Fragment>

Replace the CI token; the old one stops at once.
</RefItem>
<RefItem>
<Fragment slot="term">`ignore add --org --project --name <screenshot> --region <x,y,width,height>`</Fragment>

Ignore a rectangle (pixels from the top left) in screenshots with that name.
</RefItem>
<RefItem>
<Fragment slot="term">`ignore list --org --project`</Fragment>

List ignored regions.
</RefItem>
<RefItem>
<Fragment slot="term">`ignore remove <id> --org --project`</Fragment>

Stop ignoring a region.
</RefItem>
</RefList>

### Integrations

<RefList>
<RefItem>
<Fragment slot="term">`github link --org --project --repo <owner/name> --installation <id>`</Fragment>

Link a project to a GitHub repository (needs the GitHub App).
</RefItem>
<RefItem>
<Fragment slot="term">`github unlink --org --project`</Fragment>

Stop reporting a project to GitHub.
</RefItem>
<RefItem>
<Fragment slot="term">`webhook add --org --project --url --events <list> [--json]`</Fragment>

Add a webhook; the signing secret is printed once. Events: `build.completed`, `build.reviewed`. At least one is required.
</RefItem>
<RefItem>
<Fragment slot="term">`webhook list --org --project`</Fragment>

List a project's webhooks.
</RefItem>
<RefItem>
<Fragment slot="term">`webhook remove --org --project --id`</Fragment>

Remove one (ID from `list`).
</RefItem>
</RefList>

### Storage

<RefList>
<RefItem>
<Fragment slot="term">`storage usage [--json]`</Fragment>

Files and bytes by kind, and what waits to be deleted.
</RefItem>
<RefItem>
<Fragment slot="term">`storage migrate --to fs|s3 [--path] [--bucket] [--region] [--endpoint] [--force-path-style]`</Fragment>

Copy every stored file to another storage under the same keys.
</RefItem>
<RefItem>
<Fragment slot="term">`storage gc [--grace-hours <h>] [--dry-run]`</Fragment>

Run retention now.
</RefItem>
</RefList>

### Checks and setup

<RefList>
<RefItem>
<Fragment slot="term">`doctor`</Fragment>

Check storage, database and migrations, mail, free disk space, the dashboard address and the cookie scope of the domains. Exits 1 on a warning or failure.
</RefItem>
<RefItem>
<Fragment slot="term">`setup-code`</Fragment>

Print the code the first-run setup page asks for.
</RefItem>
<RefItem>
<Fragment slot="term">`mail test --to <email>`</Fragment>

Send a test mail through the configured SMTP server.
</RefItem>
</RefList>

<Aside type="tip">
Accounts, workspaces, projects, webhooks and storage can all be managed from here, which is the way to script a fresh install or to recover from a lockout.
</Aside>
