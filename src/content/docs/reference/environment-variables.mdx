Values are read once at start. Booleans accept `true`, `false`, `1`, `0`, `yes` and `no`. An empty value counts as unset. A bad value stops the process with a list of problems. Any variable can also be read from a file named by `<NAME>_FILE` ([Secrets](/self-hosting/configuration/#secrets)). Guidance is in [Configuration](/self-hosting/configuration/).

<InstanceSettingNote title="The Instance settings badge">
A variable with the **Instance settings** badge is also editable in the dashboard: who can create workspaces, sign-in methods and providers, the five limits (grace period, upload timeout, job retention, largest site, webhook timeout), the mail server and the Slack app. When the variable is set it wins and locks the setting ("Set by VARIABLE"); otherwise the saved value applies, otherwise the default. Saved changes apply within about 30 seconds, with no restart. The default retention of new projects is a dashboard setting with no variable. See [Instance settings](/self-hosting/instance-settings/).
</InstanceSettingNote>

Both deploys pass every variable: the [Docker Compose](/self-hosting/docker-compose/) file from `.env`, and the [Terraform module](/self-hosting/terraform/#settings) as a key of its group (`SMTP_HOST` is `smtp.host`).
