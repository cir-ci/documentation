You need three things: a folder of PNG screenshots (any test tool will do; Playwright's `page.screenshot({ path: 'screenshots/home.png' })` is enough: see [Playwright](/ci/playwright/)), your CirCI address and the project's CI token.

<Steps>

1. Set your address and token. The project's **Settings** › **CI token** page shows this snippet with your address filled in.

   ```sh
   export CIRCI_API_URL=http://localhost:3000
   export CIRCI_TOKEN=circi_…
   ```

2. Upload the folder and wait for the result.

   <CopyCommand client:visible command="npx circi upload ./screenshots --wait" />

3. Open the project in the dashboard. The build is there, with its screenshots counted by state.

</Steps>

<Aside type="note">
`npx circi` runs the CLI package, `@circi/cli`, so your CI must be able to install it. Otherwise build it from the repository (`pnpm build`) and run `packages/cli/dist/main.mjs`.
</Aside>

## What the CLI does

- Every `*.png` under the folder is a screenshot, named by its path: `settings/profile.png` becomes `settings/profile`. Hidden folders and `node_modules` are skipped; symbolic links are followed.
- An optional `<file>.png.json` next to a screenshot adds metadata (browser, viewport, test name).
- A screenshot can be at most 25 MB.
- On a CI it recognizes, it reads the commit, branch and pull request itself. Locally it uses git. Override with `CIRCI_COMMIT`, `CIRCI_BRANCH`, `CIRCI_PR_NUMBER` and `CIRCI_BASE_BRANCH`.
- It retries network errors and server errors (5xx) with growing waits, and prints how many screenshots it found.

With `--wait` it then waits for the result and exits `0` (passed), `1` (changes need review) or `2` (error). Every flag is in the [CLI reference](/ci/cli/).

## What you see

The first build of a project has nothing to compare with, so every screenshot is <StatusChip status="added" /> and the build waits for review. With no git host linked, `--wait` exits `1` until you approve.
