## Approve the baseline

<Steps>

1. Look through the screenshots. In a first build every one is <StatusChip status="added" />.
2. Approve them one by one, or approve the whole build. The build becomes <StatusChip status="approved" />, and it's now the baseline for later builds with the same name.
3. Upload the same screenshots again (a re-run). The build finishes with no changes and `circi upload --wait` exits `0`.

</Steps>

Now change a screenshot and upload from a new commit. The build shows that screenshot as changed, with the diff next to the baseline. That is the loop. [Reviewing a build](/review/reviewing-a-build/) covers the build page, shortcuts, comments and requests.

## Close the loop with your git host

- Link the project to its repository to get a **CirCI** check on pull requests with Approve and Reject buttons, and a summary comment: [GitHub](/integrations/github/), [GitLab](/integrations/gitlab/), [Bitbucket](/integrations/bitbucket/).
- Mark that check as required in the repository's branch protection to block merges until someone reviews.
- Add [Slack](/integrations/slack/) or a [webhook](/integrations/webhooks/) to hear about builds.

## Next steps
