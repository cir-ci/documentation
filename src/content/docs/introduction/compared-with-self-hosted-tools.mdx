[Chromatic, Percy and Argos](/introduction/compared-with-chromatic-percy-argos/) are services. If you want visual regression testing that runs on your own machines, the open source tools people compare CirCI with are Visual Regression Tracker, BackstopJS and Lost Pixel. They don't all do the same job: one is a server with a review dashboard like CirCI, one is a command line tool that captures and compares on its own, and one has been archived.

This page lists what each project's own README, repository and npm package say. It doesn't rank them. Facts about the other projects were read on **November 23, 2026**, and a project can change after that. Where a source says nothing about a point, this page says so and doesn't guess.

## Visual Regression Tracker

The closest to CirCI in shape: a self-hosted server with projects, builds, baselines and a review dashboard. Its README lists agents for Playwright, Cypress and CodeceptJS, SDKs for JavaScript, Java, Python and .NET, per-project comparators (pixelmatch, looks-same, odiff and vision-language models), baselines per branch, ignore areas, roles and password, LDAP or OIDC sign-in.

The difference is mostly in how screenshots get in and how the result reaches a pull request. Visual Regression Tracker takes screenshots one by one through its SDKs while the tests run. CirCI takes a folder of PNG files after the tests, through [`circi upload`](/ci/cli/) or a plugin, and reports to the [git host](/integrations/overview/) with a merge gate.

## BackstopJS

A long-standing tool that does everything in one command: `backstop test` opens the pages in its config with Playwright or Puppeteer, captures them, compares them with the reference screenshots and opens a report; `backstop approve` updates the reference. It has no server, and the reference images live in your repository.

It fits a small site where one person runs the tests and reads the report. It doesn't keep a history of builds, and the team has nowhere shared to review or comment. Its README asks for a new maintainer.

## Lost Pixel

Lost Pixel captured Storybook, Ladle and Histoire stories and app pages, or compared a folder of your own screenshots. The engine was open source, and the review UI and approval flow were part of the hosted Lost Pixel Platform. The repository is now archived, and its README announces that the team is joining Figma and sunsetting the product.

If you used Lost Pixel for Storybook, [`@circi/storybook`](/ci/storybook/) screenshots every story in your CI and uploads them. For your own screenshots, upload the folder with [`circi upload`](/ci/cli/).

## What CirCI adds

- **A shared review with a merge gate.** Builds, per-screenshot decisions, comments on regions, review requests by rule, and a check that blocks the pull request until it's reviewed. See [How a build flows](/introduction/how-a-build-flows/) and [Reviewing a build](/using/reviewing-a-build/).
- **Works with what your tests already write.** Any tool that writes PNG files, plus plugins for [Vitest](/ci/vitest/), [Cypress](/ci/cypress/) and [Storybook](/ci/storybook/); [Playwright](/ci/playwright/) needs no plugin.
- **Flaky screenshots over time.** A [triage queue](/using/triage-and-flaky-screenshots/) and [insights](/using/insights/) across builds.
- **Integrations.** GitHub, GitLab, Bitbucket, Slack, Linear, Jira, Figma and signed webhooks. See [Integrations](/integrations/overview/).
- **Hosted sites.** A built Storybook or test report next to the screenshots ([Hosted sites](/using/hosted-sites/)).

## What CirCI doesn't do

- **It doesn't take screenshots.** BackstopJS and Lost Pixel open the pages themselves; with CirCI, your tests or a plugin do.
- **It needs a server.** Postgres, file storage and a Docker host ([Requirements](/self-hosting/requirements/)). BackstopJS needs none of that.
- **No SDKs for Java, Python or .NET.** Anything that writes PNG files can upload with the CLI, but there's no per-language client like Visual Regression Tracker's.
- **It's pre-1.0.** Parts of it are verified only against fakes.

## Moving your screenshots over

There's no import from these tools. Your current baselines aren't carried over: the first build you upload and approve becomes the baseline.

1. [Run CirCI](/getting-started/run-it-locally/), [create a project](/getting-started/create-a-project/) and copy its CI token.
2. Point the upload at the folder your tool writes its new screenshots to (with BackstopJS, a run's folder under `bitmaps_test`). Each `.png` file is one screenshot, named by its path:

   ```sh
   CIRCI_TOKEN=circi_… CIRCI_API_URL=https://circi.example.com npx @circi/cli upload ./screenshots --wait
   ```

3. Approve the first build in the dashboard ([First review](/getting-started/first-review/)); later builds are compared with it.

CirCI reads PNG files only. Keep file names stable between runs: a renamed file is a new screenshot.
