CirCI is a visual regression testing tool you run yourself. Your tests take screenshots, CI uploads them to CirCI after each run, and CirCI compares every screenshot with the last approved one. When something looks different, people on your team review the change in a web dashboard and approve or reject it. The result can block a pull request from merging until someone has looked.

It is a self-hosted alternative to services such as Argos: one Docker image, a Postgres database and somewhere to keep files (local disk or any S3-compatible bucket).

## What you get

- **Uploads from CI.** The `circi` CLI uploads a folder of PNG screenshots. The `@circi/vitest` plugin takes stable screenshots from Vitest browser mode and uploads them when the run ends. Argos SDKs work too, by changing two environment variables.
- **A fast comparison.** The worker diffs each screenshot with its baseline, by default in a native Rust engine. Screenshots that haven't changed (same SHA-256) are never opened.
- **A review dashboard.** Side-by-side, overlay and swipe views, approve and reject per screenshot or per build, comments on regions of a screenshot, review requests and rules, an Inbox, saved views and insights.
- **Flaky screenshot handling.** CirCI notices screenshots that keep flipping back to an image they already had, marks them as flaky, and can let a pull request that only changes flaky screenshots pass.
- **A merge gate.** With GitHub linked, each build is a **CirCI** check with Approve and Reject buttons. Without it, the CI job itself fails until the changes are approved.
- **Integrations.** GitHub, GitLab and Bitbucket (checks or statuses, pull request comments), Slack, Linear, Jira, Figma and signed outgoing webhooks.
- **Hosted sites.** Upload a built Storybook, a Playwright report or a coverage report per commit and per branch, and open it next to the screenshots. Only members of the project's workspace can see it.

## Who it is for

Teams that want visual review without sending screenshots of internal apps to a third party, and that are comfortable running a container. A small install is one VM with Docker: see [Requirements](/self-hosting/requirements/) and [running costs](/self-hosting/storage/).
