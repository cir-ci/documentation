CirCI is a [visual regression testing](/introduction/what-is-visual-regression-testing/) tool you run yourself. Your tests take screenshots, CI uploads them after each run, and CirCI compares each one with the last approved version. When something looks different, your team reviews the change in a web dashboard and approves or rejects it. The result can block a pull request until someone has looked.

It's a self-hosted alternative to hosted services such as Chromatic, Percy and Argos ([how they differ](/introduction/compared-with-chromatic-percy-argos/), and what [visual regression testing without a SaaS](/introduction/visual-regression-testing-without-saas/) means in practice): one Docker image, a Postgres database and somewhere to keep files (local disk or any S3-compatible bucket).

## What you get

- **Uploads from CI.** The `circi` CLI uploads a folder of PNG screenshots, from [Playwright](/ci/playwright/) or any tool that writes PNG files, with [examples for each CI](/ci/ci-examples/). The `@circi/vitest` plugin takes stable screenshots in Vitest browser mode.
- **A fast comparison.** The worker diffs each screenshot with its baseline in a native Rust engine by default. Screenshots with the same SHA-256 are never opened.
- **A review dashboard.** Side-by-side, diff and slider views. Approve or reject per screenshot or per build, comment on regions, request reviews by rule, and follow it all in the [Inbox](/using/inbox-and-reviews/), [saved views](/using/saved-views/) and [insights](/using/insights/).
- **Flaky screenshot handling.** CirCI notices screenshots that keep flipping back to an image they already had, marks them <StatusChip status="flaky" />, and can let a pull request that only changes flaky screenshots pass.
- **A merge gate.** With a git host linked, each build is a **CirCI** check with Approve and Reject buttons. Without one, the CI job fails until the changes are approved.
- **Integrations.** GitHub, GitLab and Bitbucket (checks or statuses, pull request comments), Slack, Linear, Jira, Figma and signed outgoing webhooks.
- **Hosted sites.** Upload a built Storybook, a Playwright report or a coverage report per commit and per branch, and open it next to the screenshots. Only members of the project's workspace can see it.

## Who it's for

Teams that want visual review without sending screenshots of internal apps to a third party, and that are comfortable running a container. A small install is one VM with Docker: see [Requirements](/self-hosting/requirements/) and [running costs](/self-hosting/storage/).
