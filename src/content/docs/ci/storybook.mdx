CirCI has no Storybook add-on, and it doesn't need one. CirCI compares PNG files, so Storybook visual testing with CirCI is two steps: write one screenshot per story, then upload the folder. This page shows two ways to take the screenshots, and both end in the same place. For how CirCI differs from services that capture stories for you, see [Compared with Chromatic, Percy and Argos](/introduction/compared-with-chromatic-percy-argos/).

| | Playwright over a built Storybook | Vitest with portable stories |
|---|---|---|
| **What renders the story** | Storybook itself, in the preview page of a static build | Your test, with `composeStories` from Storybook's portable stories |
| **Covers** | Every story in the build, found in Storybook's `index.json`, with your `.storybook` setup applied | The story files you list in a test |
| **Needs** | A built Storybook, a static file server, Playwright | Vitest browser mode and `@circi/vitest` |
| **Uploads with** | `circi upload` | The plugin, when the run ends |

<Aside type="note" title="What was run">
Both routes were run end to end in a scratch React project (Storybook 10.6.8 with `@storybook/react-vite`, Playwright 1.65.1 on Chromium, Vitest 5.1.1, `@circi/vitest` 0.3.0 and `@circi/cli` 0.2.0, the published packages) against a CirCI server started from the repository's `pnpm dev`. Each route wrote its PNG files, and the upload created a build whose screenshots had the names shown below. Not tried: frameworks other than React, Storybook's own Vitest add-on, decorators and parameters from `.storybook/preview`, and the same steps inside a real CI service. The build was not reviewed or compared against a baseline here, so how a second run looks is described by CirCI's ordinary behavior, not by this run.
</Aside>

## Route 1: Playwright over a built Storybook

Build Storybook, serve the folder, and let a short script open each story in the preview page and take its screenshot.

<Steps>

1. Build Storybook as a static site:

   ```sh
   npx storybook build -o storybook-static
   ```

   The folder has an `index.json` listing every story, and an `iframe.html` that renders one story alone.

2. Install Playwright next to it, and its browser:

   ```sh
   npm install --save-dev playwright
   npx playwright install --with-deps chromium
   ```

3. Save the script as `storybook-screenshots.mjs`:

   ```js title="storybook-screenshots.mjs"
   // Takes one PNG per story of a built Storybook, for `circi upload`.
   import { mkdir } from 'node:fs/promises'
   import { dirname, join } from 'node:path'
   import { chromium } from 'playwright'

   const base = process.env.STORYBOOK_URL ?? 'http://127.0.0.1:6006'
   const out = process.env.SCREENSHOT_DIR ?? 'screenshots'
   const slug = (text) => text.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')

   const index = await (await fetch(`${base}/index.json`)).json()
   const stories = Object.values(index.entries).filter((entry) => entry.type === 'story')

   const browser = await chromium.launch()
   const page = await browser.newPage({ viewport: { width: 800, height: 600 } })
   try {
     for (const story of stories) {
       await page.goto(`${base}/iframe.html?id=${story.id}&viewMode=story`)
       await page.waitForSelector('body.sb-show-main, body.sb-show-errordisplay')
       if (await page.locator('body.sb-show-errordisplay').count()) {
         throw new Error(`${story.id} failed to render`)
       }
       await page.evaluate(() => document.fonts.ready)
       // components/button/primary.png is the screenshot "components/button/primary" in CirCI.
       const file = join(out, ...story.title.split('/').map(slug), `${slug(story.name)}.png`)
       await mkdir(dirname(file), { recursive: true })
       await page.screenshot({ path: file, animations: 'disabled', caret: 'hide' })
       console.log(file)
     }
   } finally {
     await browser.close()
   }
   ```

4. Serve the build, run the script, and upload the folder:

   ```sh
   npx http-server storybook-static -p 6006 -a 127.0.0.1 -s &
   node storybook-screenshots.mjs
   npx @circi/cli upload ./screenshots --name storybook --wait
   ```

   Any static file server works in place of `http-server`. `CIRCI_TOKEN` and `CIRCI_API_URL` are set as in [the CLI reference](/ci/cli/).

</Steps>

For a two-story Button the script printed `screenshots/components/button/primary.png` and `screenshots/components/button/secondary.png`, and the upload created a build with the screenshots `components/button/primary` and `components/button/secondary`. The path is the name, so a story's name in CirCI is its Storybook title and story name, and moving a story to another title is a new screenshot.

What the script does, and where to change it:

- **A story that throws** stops the run with its ID, instead of uploading a screenshot of Storybook's error screen.
- **Size.** The viewport is fixed at 800 by 600. A different size is always a change, so set it once, and take a locator's screenshot (`page.locator('#storybook-root').screenshot(...)`) when you want only the component.
- **Skipping stories.** The loop sees every entry of `index.json` with `type` `story`. Filter on `entry.tags` (a tag of your own such as `skip-visual`) to leave some out.
- **Stories with a `play` function.** The script waits for Storybook to say the story rendered, which may be before the `play` function finishes. If the screenshot should show its result, wait for something the function changes (`await page.locator('...').waitFor()`) before taking it. That case wasn't run here.

## Route 2: Vitest with portable stories

If your components already have Vitest browser tests, a test can render each story with Storybook's portable stories and let the [Vitest plugin](/ci/vitest/) capture it. Install `vitest`, `@vitest/browser-playwright`, `vitest-browser-react`, `@circi/vitest` and, for a Vite and React project, `@vitejs/plugin-react`.

```js title="vitest.config.js"
import { circi } from '@circi/vitest'
import react from '@vitejs/plugin-react'
import { playwright } from '@vitest/browser-playwright'
import { defineConfig } from 'vitest/config'

export default defineConfig({
  plugins: [react(), circi({ name: 'storybook' })],
  test: {
    include: ['src/**/*.visual.test.jsx'],
    browser: {
      enabled: true,
      headless: true,
      provider: playwright(),
      instances: [{ browser: 'chromium' }],
      viewport: { width: 800, height: 600 },
    },
  },
})
```

```jsx title="src/Button.visual.test.jsx"
import { composeStories } from '@storybook/react-vite'
import { expect, test } from 'vitest'
import { render } from 'vitest-browser-react'
import * as stories from './Button.stories.jsx'

// One screenshot per story, named by the story's export: "Primary" is the name "primary".
for (const [name, Story] of Object.entries(composeStories(stories))) {
  test(name, async () => {
    const screen = await render(<Story />)
    await expect.element(screen.container).toMatchScreenshot(name.toLowerCase())
  })
}
```

Run `CIRCI_API_URL=… CIRCI_TOKEN=… npx vitest run`. The plugin wrote `.circi/screenshots/src/Button.visual.test.jsx/primary.png` (and `secondary.png`) and uploaded them when the run ended, as the builds' screenshots `src/Button.visual.test.jsx/primary` and `src/Button.visual.test.jsx/secondary`: the test file's path, then the name you passed ([names](/ci/vitest/#names)). Add one test file per stories file.

<Aside type="caution" title="Your Storybook setup">
Decorators, global parameters and CSS that your stories get from `.storybook/preview` are not applied by `composeStories` unless you pass the preview's annotations to Storybook's `setProjectAnnotations` first (see Storybook's [portable stories documentation](https://storybook.js.org/docs/api/portable-stories/portable-stories-vitest)). The scratch project had no preview file, so that wasn't run. Route 1 applies the preview file, because Storybook itself renders the story.
</Aside>

## In CI

Upload from the job that builds and screenshots, with the project's token as the secret `CIRCI_TOKEN`. Give the build its own name (`--name storybook` above, or `name` in the plugin) so its baselines are separate from your end-to-end screenshots ([several builds per commit](/ci/ci-examples/#several-builds-per-commit)). The same job can also upload the built Storybook as a hosted site with `circi storybook upload ./storybook-static` ([Hosted sites](/using/hosted-sites/)); that command wasn't part of this run.

The setup guides have the full workflows: [GitHub Actions](/ci/github-actions/) and [GitLab CI](/ci/gitlab-ci/). The first build has no baseline, so approve every screenshot once ([First review](/getting-started/first-review/)).

## Make story screenshots stable

CirCI marks a pixel as changed once its color moves past a fixed tolerance, and the default diff threshold is 0% ([How screenshots are compared](/introduction/how-screenshots-are-compared/)). Run the screenshots on the same machine image every time (fonts differ between operating systems), keep the viewport fixed, and keep data and dates in stories fixed. For a part that still moves, draw an [ignore region](/using/baselines-and-ignore-regions/#ignore-regions).
